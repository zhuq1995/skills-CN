# 代码审查技能

审查 Git 仓库中已修改但未提交的代码变更。

## 工作流程

1. **获取 git 状态**: 运行 `git status` 列出所有已修改、已暂存和未跟踪的文件
2. **获取 git diff**: 运行 `git diff` 查看所有未暂存的变更，运行 `git diff --staged` 查看已暂存的变更
3. **读取变更文件**: 对于重要变更，读取已修改的文件以了解上下文
4. **分析与报告**: 提供全面的审查，包括：
   - 变更摘要（修改的文件、新增/删除的行数）
   - 代码质量问题（风格、复杂性、模式）
   - 潜在的 Bug 或错误
   - 安全问题
   - 改进建议
   - 变更是否可以提交

## 输出格式

按以下结构呈现审查结果：

```
## 代码审查报告

### 变更概览
- 修改文件数: X
- 新增行数: +X
- 删除行数: -X

### 文件审查详情

#### [文件名] (`路径`)
**变更类型**: [新增/修改/删除]

**变更内容**:
```
// relevant diff or code snippet
```

**审查意见**:
- [+] 优点
- [!] 问题/风险
- [?] 疑问
- [建议] 改进方案

### 整体评估
- [ready-to-commit / needs-work / requires-discussion]
- 主要发现和建议总结
```

## 审查重点领域

- **代码质量**: 可读性、复杂性、重复代码、设计模式
- **潜在 Bug**: 逻辑错误、边界条件、空值处理、资源泄漏
- **安全问题**: 注入风险、认证/授权问题、敏感信息泄露
- **最佳实践**: 错误处理、日志记录、测试覆盖
- **项目规范**: 遵循 CLAUDE.md 中的代码风格要求

## 特殊情况

- **大型差异 (>500 行)**: 重点关注高层摘要和关键文件，询问用户是否需要对特定文件进行详细审查
- **生成的文件**: 跳过对压缩/生成文件的详细审查
- **配置变更**: 审查安全性和正确性，而非代码风格
- **迁移文件**: 验证向后兼容性

## Git 命令参考

```bash
git status              # 查看所有变更
git diff                # 未暂存的变更
git diff --staged       # 已暂存的变更
git diff HEAD           # 所有变更（包括未暂存和已暂存）
git diff --stat         # 变更统计
git diff [file]         # 指定文件变更
```
