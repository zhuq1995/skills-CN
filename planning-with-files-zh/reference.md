# 参考：Manus上下文工程原则

此技能基于Manus的上下文工程原则，Manus是被Meta于2025年12月以20亿美元收购的人工智能代理公司。

## 6个Manus原则

### 1. 文件系统作为外部记忆

> "Markdown是我在磁盘上的'工作内存'。"

**问题：** 上下文窗口有限。将所有内容塞入上下文会降低性能并增加成本。

**解决方案：** 将文件系统视为无限内存：
- 将大内容存储在文件中
- 上下文中只保留路径
- 代理可以在需要时"查找"信息
- 压缩必须是**可逆**的

### 2. 通过重复操纵注意力

**问题：** 在~50个工具调用后，模型会忘记原始目标（"中间遗忘"效应）。

**解决方案：** 保留一个 `.claude_tasks/task_xxxx/task_plan.md` 文件，在整个执行过程中**重新读取**：
```
上下文开头：[原始目标 - 很远，已遗忘]
...许多工具调用...
上下文末尾：[最近读取的 task_plan.md - 获得注意力！]
```

通过在每次决策前阅读计划文件，目标会出现在注意力窗口中。

### 3. 保留失败痕迹

> "错误恢复是真正代理行为最清晰的信号之一。"

**问题：** 本能是隐藏错误、静默重试。这会浪费token并失去学习机会。

**解决方案：** 在计划文件中保留失败的操作：
```markdown
## 遇到的错误
- [2025-01-03] FileNotFoundError: config.json 未找到 → 创建了默认配置
- [2025-01-03] API超时 → 使用指数退避重试，成功
```

当模型看到失败时会更新其内部理解。

### 4. 避免小样本过拟合

> "一致性产生脆弱性。"

**问题：** 重复的操作-观察对会导致漂移和幻觉。

**解决方案：** 引入受控变化：
- 稍微改变措辞
- 不要盲目复制粘贴模式
- 重新校准重复性任务

### 5. 稳定前缀以优化缓存

**问题：** 代理输入密集（100:1比例）。每个token都花钱。

**解决方案：** 为缓存命中而构建结构：
- 将静态内容放在**首位**
- 仅追加上下文（永不修改历史）
- 一致的序列化

### 6. 仅追加上下文

**问题：** 修改之前的消息会使KV缓存失效。

**解决方案：** **永不**修改之前的消息。始终追加新信息。

## 代理循环

Manus在连续循环中运行：

```
1. 分析 → 2. 思考 → 3. 选择工具 → 4. 执行 → 5. 观察 → 6. 迭代 → 7. 交付
```

### 循环中的文件操作：

| 操作 | 使用时机 |
|------|----------|
| `write` | 新文件或完全重写 |
| `append` | 增量添加部分 |
| `edit` | 更新特定部分（复选框、状态） |
| `read` | 决策前审查 |

## 关键语录

> "如果模型改进是涨潮，我们希望Manus是船，而不是钉在海底的桩。"

> "对于复杂任务，我将笔记、代码和发现保存到 `.claude_tasks/task_xxxx/` 目录下的文件中，以便在工作时可以参考它们。"

> "我使用 Edit 工具来更新计划中的复选框，而不是重写整个文件。"
